# EyeNED web interface — DESIGN.md

Design rules for `client/`, implementing ADR 0006 (`Eyened/designdocuments`,
`decisions/0006-web-ui-design-system.md`) with IBM's [Carbon Design System](https://www.carbondesignsystem.com/).
Values from `@carbon/themes` 11.83.0, `@carbon/type` 11.69.0 and `@carbon/styles` 1.117.0 (not installed). `src/app.css` is
the token source; change this file in the same commit as any value there.

## Overview

- Every screen is dark: Carbon Gray 100.
- Components are shadcn-svelte (bits-ui) restyled to Carbon; callers keep shadcn's props.
- The viewer meets WCAG 2.2 AA, which includes ADR 0006's WCAG 2.1 AA text contrast.

## Layout

- Spacing: Carbon's [scale](https://www.carbondesignsystem.com/building-blocks/foundations/spacing/overview)
  only — `0.5 1 2 3 4 6 8 10 12 16 20 24 40`. Exceptions: Button padding `1.5 2.5 3.5 3.75 15.75`
  (Carbon's values minus the 1 px border), Button max width, login column and study block form card `max-w-80` (20 rem), the header's and side nav's 3 px current-item bar `0.75`, the side nav `w-64` (Carbon's 256 px), and the inline notification insets `3.25 3.5 3.75 13` (Carbon's values), the modal footer buttons `pt-3.5 pb-8`, the text area `pt-2.75`, the icon tooltip `py-0.5`, the tooltip `max-w-72`, the progress bar `min-w-12`, the table skeleton button `w-37.5` (Carbon's 150 px), the modal widths and heights (Carbon's percentages as fractions), the dropdown menu `max-h-66` / md `max-h-55` (5.5 items) and inline menu `min-w-72 max-w-120` (288 / 480 px), the expanded table row `ps-14` (3.5 rem), and the pagination select `pe-9` (2.25 rem), the content switcher lg padding `px-3.5` (14 px), the number input `min-w-37.5` (150 px), the calendar `w-72` (288 px) and its today dot `bottom-1.75` (7 px), the condition builder popover `max-h-88 max-w-80 min-w-48` (22 / 20 / 12 rem), and the `ui/command` list `max-h-75` (shadcn's 300 px, for its other callers), the tag `max-w-52` (208 px), the tag popovers `w-92` (368 px), the filter popovers `w-72` (288 px, also the `ui/popover` default), the profile popover `w-64` (256 px), the side panel `w-120 min-w-64` (30 / 16 rem), and the combo box `pe-17.5` and clear button `end-11.25` (70 / 45 px) and menu `max-h-55` (220 px).
- Header 48 px (`h-12`), fixed; content below it (`mt-12`) in `<main class="px-4 md:px-8 cds-max:px-10">`, full width at every size
  ([2x Grid, High-density interface model](https://carbondesignsystem.com/building-blocks/foundations/2x-grid/guidelines/#high-density-interface-model)).
  The inset is Carbon's grid margin plus half its 32 px gutter: 16 px below `md`, 32 px from `md`, 40 px from `cds-max`
  ([2x Grid, Breakpoints](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview#breakpoints)).
- Browser filter column: `w-full max-w-80`, slides over the results at every width, toggled by Filters ([UI shell left panel, Non-persistent left panel](https://carbondesignsystem.com/building-blocks/core/components/ui-shell-left-panel/accessibility/)); collapsed, the toggle shows the filter count and Clear filters ([Filtering, Filter states](https://www.carbondesignsystem.com/building-blocks/core/patterns/filtering)). On `/` an `overlay` scrim dims everything below the header and closes the column on click; in the picker a scrim over the results does the same. Search and Clear filters stay pinned to the bottom of the visible column.
- Reflow: every screen works at 320 CSS px wide. Nothing is cut off or overlapping, no information or action is lost (truncated text follows the Carbon component's overflow guidance), and every action can be reached by scrolling vertically only ([WCAG 2.1 SC 1.4.10](https://www.w3.org/WAI/WCAG21/Understanding/reflow.html)). Exempt, as WCAG allows: the image canvas and a data table's grid, which scroll in their own box; the table toolbar and pagination still reflow.
- Mobile-first: unprefixed classes are the narrow layout; breakpoint prefixes add to it ([Tailwind, Responsive design](https://tailwindcss.com/docs/responsive-design)). Breakpoints are Carbon's `md` 42rem, `lg` 66rem, `xlg` 82rem ([2x Grid](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview)). A component follows the breakpoint behaviour its Carbon page specifies. Carbon's `max` 99rem is `cds-max`.

## Shapes

Square corners; the radii are rounded-checkbox, rounded-tooltip and rounded-popover (2 px each), rounded-content-switcher (4 px) and rounded-tag (16 px), Carbon's; the tag close button is a circle (`rounded-full`). Shadows: `shadow-popover` for menus (Carbon tooltips have none); `shadow-button-focus` for Button focus; `shadow-content-switcher-selected` (an inset 1 px `border-inverse` ring) for the selected content switcher option. The tag popovers and the profile popover use `drop-shadow-popover` (Carbon's `drop-shadow(0 2px 2px rgba(0,0,0,0.2))`); the filter popovers use `shadow-popover`, as menus. Motion: `animate-loading-rotate` (690 ms) for the loading spinner; `animate-skeleton` (3000 ms) for skeletons.

## Keyboard & Focus

- Every focusable element shows a 2 px `focus` ring inside its edge (checkbox: 1 px outside, as Carbon draws it). Never `outline-none` or
  `outline-hidden`.
- Buttons: `focus` border plus `shadow-button-focus`; Link (`ui/button` `variant="link"` only): 1 px `focus` outline; a plain `<a>` gets the 2 px ring.
- Modal: focus starts on the first field (danger: Cancel; a `hasScrollingContent` modal with no leading field: its body region; `focusSecondary`: the secondary button, a deviation for the isn't-complete modal); while submitting, focus parks on the primary button, which is aria-disabled, not disabled.
- Pagination: Previous and Next are aria-disabled at the ends; reaching the last page moves focus to Previous, reaching page 1 to Next (Carbon React).
- Content switcher: ←/→ move between options (wrapping); automatic selects on the move, manual on Enter or Space.
- Browser filter column: while it is open, Tab and Shift+Tab wrap inside it; Escape closes it and returns focus to Filters.
- Tabs: one Tab stop; ←/→ move and select, wrapping ([Tabs, Keyboard interactions](https://carbondesignsystem.com/building-blocks/core/components/tabs/accessibility/#keyboard-interactions)).
- Multiselect (filterable): Enter or a click toggles the focused option and keeps the menu open; Space types into the filter, as Carbon's combo box does (it would otherwise submit a space into the filter string; [Dropdown, Combo box](https://carbondesignsystem.com/building-blocks/core/components/dropdown/accessibility/#combo-box)); Delete with the menu closed clears all; Escape closes ([Dropdown, Multiselect](https://carbondesignsystem.com/building-blocks/core/components/dropdown/accessibility/#multiselect)).
- Profile popover: opening focuses its first button; Tab moves between items; Escape closes and returns focus to the username (deviation below).
- New segmentation popover: opening focuses the feature combo box; Esc closes and returns focus to New (deviation above).
- Condition builder: one Tab stop; ←/→ move through every part, ↑/↓ to the same part of the next condition;
  Enter or Space opens a part's popover, which traps focus and returns it to the part on close; Escape clears a
  search field first, then closes.

## Do's and Don'ts

- Token classes only; no hex, `rgb()` or named colours in components, `<style>` or `style=`.
    - Exempt until the S2 viewer replaces it: the old viewer (`src/lib/viewer-window/`, `src/lib/viewer/`). Only visible defects are fixed there. The image
      area is `#000000`; image drawings (segmentations, points, grids) keep their own colours.
- No arbitrary values (`p-[13px]`), no `dark:`.
- Carbon spacing steps only (see Layout).
- Status = icon + label; colour on the icon.
- One primary button per view; danger only for destructive actions.
- Button icons go after the label, at most one per button. The button pins its icon to the right
  edge, as Carbon does; there is no leading-icon variant.
- Merge classes with `cn`/`tv` from `$lib/utils`, never `tailwind-merge`/`tailwind-variants` directly.
