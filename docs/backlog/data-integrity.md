# Data integrity

### Give the segmentation zarr store a cross-process write lock
- **Status:** open
- **Source:** PR #219 review, 2026-08-24
- **Problem:** the singleton `ZarrStorageManager` has no lock: `ZarrArray._append_to_array` is check-then-act on length, `get_array` is check-then-create, `write_slice` rewrites a whole-segmentation chunk. Probed in the threadpool: 8 concurrent creates all got index 0 (7 lost), 8 slice writes zeroed 3; the loss commits to MySQL silently. Gunicorn `WORKERS=4`, the CLI and the importer hit the same interleaving across processes today.
- **Fix:** a cross-process lock or a backend with one, swapped in at `get_segmentation_data_store` (`SegmentationDataStore` protocol). Until then the five zarr handlers in `server/routes/segmentations.py` must stay `async def`.

### Add `eorm move-patient` / `move-images` for cross-project data cleaning
- **Status:** open
- **Source:** PR #222 review question, 2026-08-25
- **Problem:** after #222 a cross-project move is only raw SQL: declare destination on `TaskProject` → `UPDATE Patient SET ProjectID` (or re-point `ImageInstance.SeriesID` **and** `ProjectID`) → prune unused declarations, in one transaction. `populate_project_ids` handles `session.new` only, so an ORM re-parent fails on a bare FK error. Moves leave `FormAnnotation` / `AttributeValue` / `Segmentation.SubTaskID` straddling projects, write no `AuditLog`, and fail on identifier collisions (`ProjectIDPatientIdentifier_UNIQUE`) with no pre-check.
- **Fix:** a CLI command that runs declare → move → prune in one transaction, pre-checks identifier collisions, writes `AuditLog`, and reports the straddles it created.
- **Note:** pre-declaring hides the task from source-only members immediately, so the three steps must not run as separate sessions.

### Make the database the only maintainer of `DateModified`
- **Status:** open
- **Source:** descoped from PR #222, 2026-08-27
- **Problem:** `AnnotationData`, `FormAnnotation`, `ImageStorage`, `ImageInstance` still declare `onupdate=func.now()` alongside the DB's `ON UPDATE CURRENT_TIMESTAMP`; not wrong today, but a reader cannot tell which is authoritative.
- **Fix:** drop the four `onupdate=func.now()`, keep `server_onupdate=FetchedValue()`, and pin per affected repository that a flush-only transaction serialises the value the DB holds.

### Decide DDL defaults for the `Inactive` columns
- **Status:** open, low priority
- **Source:** descoped from PR #222, 2026-08-27
- **Problem:** `Annotation.Inactive`, `Segmentation.Inactive`, `FormAnnotation.Inactive` are `NOT NULL` with no default, unlike `ImageInstance.Inactive` / `ImageStorage.IsPrimary`. Nothing fails today.
- **Fix:** decide deliberately; adding defaults is a schema change (autogenerated migration).
