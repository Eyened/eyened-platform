# Frontend CI — Phase 2 (Formatting baseline · prettier) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `prettier` a real, green CI gate for `client/` — wire the config so it actually covers `.svelte` (not just `.ts`/`.js`/`.json`), normalize the whole tree with one isolated mechanical `prettier --write .` commit, and add the `format:check` step to `client-ci.yml`.

**Architecture:** Three small commits, mechanical diff isolated in the middle. (1) Fix `.prettierrc` so the Svelte parser engages + add a `.prettierignore` for generated/build artifacts + add `format`/`format:check` scripts — this is the meaningful config change, reviewable on its own and deliberately still *red*. (2) `prettier --write .` — one large, behavior-free reformat commit that turns the gate green. (3) Add the `format:check` step to the CI workflow — a trivial, isolated change. Order guarantees `client-ci` is never red: the gate step lands only after the tree is formatted.

**Tech Stack:** prettier 3 (already installed, `^3.1.0`), `prettier-plugin-svelte` (already installed, `^3.2.6`), `prettier-plugin-tailwindcss` (already installed, `^0.6.11`), node 24. **No new dependencies.**

## Global Constraints

- **Runtime:** node **24** (already pinned via `client/.nvmrc` = `24` from Phase 1). All local verification runs under node 24 — activate it first in every task: `. "$HOME/.nvm/nvm.sh" && nvm use 24`.
- **Zero new dependencies.** `prettier`, `prettier-plugin-svelte`, and `prettier-plugin-tailwindcss` are already in `client/package.json` devDeps. Do **not** run `npm install`. If any step reports a missing plugin, stop — that is a real finding, not a cue to add deps.
- **Plugin order is load-bearing:** `prettier-plugin-tailwindcss` **must be the last** entry in the `plugins` array (its docs require it) — `prettier-plugin-svelte` goes *before* it.
- **The reformat commit (Task 2) changes zero behavior.** It is `prettier --write .` and nothing else — no hand edits mixed in. Keep it isolated so reviewers can approve it by diff shape, not line-by-line.
- **Phase-2 CI gate adds exactly one step: `format:check`.** Do **not** add `lint` (Phase 3) or `check` (Phase 4) — those are still red. Step order in `client-ci.yml` equals phase order: `verify:runes` → `test` → `build` → **`format:check`**.
- **Do not touch** `tsconfig.json`, `vite.config.ts`, `.eslintrc.cjs`, or any test files in this phase. Formatting-only.
- **Work happens on branch `feature/frontend-ci-testing`** in the worktree `/home/kdatta/workspace/eyened-platform-worktrees/frontend-ci-testing` (upstream unset; do not push). Commit per task. All `cd` targets are under `client/` unless stated.

## File Structure

**Create:**
- `client/.prettierignore` — excludes generated + build artifacts from formatting so the gate is stable (`.svelte-kit/` is regenerated by `svelte-kit sync` on every `npm ci`; the `openapi*` types are regenerated from the backend spec and would re-diverge if we reformatted them).

**Modify:**
- `client/.prettierrc` — add `prettier-plugin-svelte` to `plugins` (before `prettier-plugin-tailwindcss`) so `.svelte` files get a parser. Without this they are silently skipped (`No parser could be inferred`).
- `client/package.json` — add `format` (`prettier --write .`) and `format:check` (`prettier --check .`) scripts.
- **Every formatted file under `client/`** — the mechanical output of `prettier --write .` in Task 2 (`.ts`/`.js`/`.json`/`.svelte`/`.css`/`.md`, minus `.prettierignore` entries). This is a large, generated diff, not hand edits.
- `.github/workflows/client-ci.yml` — add the `format:check` step after `build`.

**Note on the reformat's size:** the design's dry run measured **157 files** — but that run had **no Svelte parser wired**, so it counted only `.ts`/`.js`/`.json`. Once `prettier-plugin-svelte` is added, the ~310 `.svelte` files become eligible too, so Task 2's diff will be **substantially larger than 157 files**. That is expected and correct — it is the first time `.svelte` files are formatted in this repo.

- [ ] **Step 3: Add the Svelte plugin to `.prettierrc`**

Replace the entire contents of `client/.prettierrc` with (keeps `tabWidth`/tailwind settings; adds the svelte plugin *before* tailwindcss):

```json
{
    "tabWidth": 4,
    "plugins": [
        "prettier-plugin-svelte",
        "prettier-plugin-tailwindcss"
    ],
    "tailwindStylesheet": "./src/app.css"
}
```

- [ ] **Step 4: Verify the Svelte parser now engages**

```bash
npx prettier --check src/routes/+layout.svelte
```

Expected: **no** `No parser could be inferred` error. Output is now either `[warn] src/routes/+layout.svelte` (needs formatting — most likely) or `All matched files use Prettier code style!`. Either proves the parser is wired.

Fallback (only if it still says `No parser could be inferred`): add an explicit override to `.prettierrc` and re-run Step 4:

```json
    "overrides": [
        { "files": "*.svelte", "options": { "parser": "svelte" } }
    ]
```

(Insert as a sibling key after `tailwindStylesheet`. With `prettier-plugin-svelte@3` the plugin auto-registers the parser, so this is normally unnecessary.)

- [ ] **Step 5: Create `client/.prettierignore`**

Create `client/.prettierignore` with:

```gitignore
# Framework build output — regenerated by `svelte-kit sync` / `vite build`
.svelte-kit/
build/
dist/

# Dependency + lock artifacts
node_modules/
package-lock.json

# Generated from the backend OpenAPI spec — reformatting these would re-diverge
# on the next regen and make the gate flaky. Hand-written *.d.ts are NOT ignored.
src/types/openapi.ts
src/types/openapi.json
src/types/openapi_types.ts
src/types/openapi_constants.ts

# GLSL shader sources. Prettier has NO GLSL parser, and it maps `.frag` to its
# babel/JS parser — so it throws `SyntaxError` on valid GLSL (e.g. `for(int i…)`)
# and exits 2. Not a style opinion: prettier fundamentally cannot read these.
*.frag
*.vert
*.glsl
```

- [ ] **Step 6: Add the `format` and `format:check` scripts**

In `client/package.json`, add these two entries to the `"scripts"` object (place them next to the existing `test` scripts):

```json
    "format": "prettier --write .",
    "format:check": "prettier --check ."
```

- [ ] **Step 7: Confirm the config engages the whole tree and is (expectedly) red**

```bash
npm run format:check
```

Expected: **FAILS with exit 1**, printing `[warn] ...` lines that now **include `.svelte` files** (e.g. `[warn] src/routes/+layout.svelte`) and ending with `Code style issues found in <N> files.` where `<N>` is well above 161 (the pre-svelte-plugin count). This red state is the deliverable — Task 2 turns it green.

**Exit code is load-bearing — check it, don't just eyeball the output.** Prettier exits **1** for "files differ" (what we want here) and **2** for "an error occurred" (a file it could not parse). Do not accept exit 2: prettier prints `[error] <file>: SyntaxError…` *and still prints* `All matched files use Prettier code style!`, so the success text is not evidence. If you see exit 2, find the `[error]` line — an unparseable file type is escaping `.prettierignore`:

```bash
npm run format:check; echo "EXIT=$?"    # want EXIT=1 here, never EXIT=2
```

Sanity check that `.prettierignore` works — this must print nothing:

```bash
npx prettier --list-different . | grep -E '\.svelte-kit/|src/types/openapi' || echo "OK: generated/build files excluded"
```

Expected: `OK: generated/build files excluded`.

## Notes for later phases (not this phase)

- **Phase 3 `lint` should be `eslint .` only — not `eslint . && prettier --check .`.** The design's scripts block combines them, but with a dedicated `format:check` step already in CI (this phase), folding `prettier --check` into `lint` would run prettier twice per CI run. Drop the `&& prettier --check .` from `lint` when Phase 3 lands.
- **`.prettierignore` and `eslint.config.js` ignores must stay consistent** in Phase 3 (both should skip `.svelte-kit/`, `build/`, generated `openapi*`).
