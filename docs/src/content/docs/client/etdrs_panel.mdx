The **ETDRS** panel lets you place, review, and persist ETDRS grid coordinates on 2D enface images (for example color fundus). The grid is centered on the fovea and scaled using the fovea-to-optic-disc distance.

## Prerequisites

The ETDRS panel appears only when:

1. The current image is **2D** (not a volume or OCT stack).
2. A `FormSchema` named **`ETDRS-grid coordinates`** exists in the database.

On a fresh deployment, run:

```bash
eorm seed-form-schemas
```

See **[Form Schemas](/eyened-platform/orm/form_schemas)** for details on builtin schemas.

## Automatic vs manual grids

There are two sources of ETDRS coordinates:

| Source | Where it lives | Editable | Saved to database |
|--------|----------------|----------|-------------------|
| **Automatic** | `ImageInstance.CFKeypoints` (AI inference on import) | No (read-only overlay) | Already on the image row |
| **Manual** | `FormAnnotation.FormData` | Yes (edit tool) | Yes, via form annotation API |

When AI keypoints are present, the panel shows an **Automatic** row. Toggle it to preview the grid from `cf_keypoints`. This does **not** create a form annotation.

To persist or adjust coordinates, click **Create new**, then use the edit tool.

## Workflow

1. Open a 2D image in the viewer.
2. Select the **ETDRS** panel in the sidebar.
3. Optionally toggle **Automatic** to preview AI-detected landmarks.
4. Click **Create new** to add a manual annotation (starts with empty coordinates).
5. Activate the **edit** tool on the new annotation.
6. Click in the image:
   - **Left click** — set **fovea**
   - **Right click** — set **optic disc edge**
7. Toggle **show/hide** on the annotation to display or hide the grid overlay.

Annotations from linked or registered images may also appear in the list when registration connects them to the current view.

## Grid geometry

The overlay draws three concentric circles with diameters **1 mm** (central), **3 mm** (inner), and **6 mm** (outer), centered on the fovea.

Scale is derived from the pixel distance between fovea and disc edge, assuming that segment represents **3 mm × radius fraction**. The default radius fraction is **0.85** and can be adjusted in the panel.

### Keyboard shortcuts

When an ETDRS overlay is active:

| Keys | Action |
|------|--------|
| `C` | Cycle central subfield circles (C0, C1, C2) |
| `I` | Cycle inner subfield circles (I1, I2) |
| `O` | Cycle outer subfield circles (O1, O2) |

Hold **Shift** while clicking to avoid placing landmarks when the edit tool is active.

## Measure panel integration

The **Measure** panel can use ETDRS coordinates to estimate image resolution (µm/pixel). Select an ETDRS annotation linked to the current image and set the same radius fraction used in the ETDRS panel.

## Data model

### FormSchema

Manual ETDRS grids use the builtin schema **`ETDRS-grid coordinates`** with `EntityType = ImageInstance`.

### FormAnnotation

Each manual grid is a `FormAnnotation` row with:

- `FormSchemaID` → ETDRS-grid coordinates schema
- `ImageInstanceID` → the annotated image
- `PatientID`, optional `StudyID`, `Laterality`
- `CreatorID` → user who created the annotation
- optional `SubTaskID` → workflow link when opened from a task

### FormData JSON shape

Coordinates are stored in **full-resolution image pixel space**:

```json
{
  "fovea": { "x": 1024.5, "y": 768.2 },
  "disc_edge": { "x": 512.0, "y": 640.0 }
}
```

The client writes this via `PUT /api/form-annotations/{id}/value`.

### AI keypoints (automatic overlay)

AI-detected landmarks are stored separately on the image:

```json
{
  "fovea_xy": [1024, 768],
  "disc_edge_xy": [512, 640],
  "prep_fovea_xy": […],
  "prep_disc_edge_xy": […]
}
```

These are written to `ImageInstance.CFKeypoints` by the CFI keypoints model (`eorm run-models`) during import or preprocessing. The API exposes them as `instance.cf_keypoints`.

:::note
The ETDRS panel reads AI keypoints for preview only. Saving manual coordinates creates or updates a **FormAnnotation**, not `CFKeypoints`.
:::

### Relationship to ETDRS area summaries

The ORM command `eorm run-etdrs-model` computes ETDRS subfield areas from segmentations and keypoint/attribute data — not directly from FormAnnotation coordinates unless those values are also present in attributes or `CFKeypoints`. See **[CLI: run-etdrs-model](/eyened-platform/orm/cli#run-etdrs-model)**.
