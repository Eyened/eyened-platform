The **ETDRS** panel lets you place, review, and persist ETDRS grid coordinates on 2D enface images (for example color fundus). The grid is centered on the fovea and scaled using the fovea-to-optic-disc distance.

## Using the panel

### When it appears

The ETDRS panel is available when the current image is **2D enface** (not a volume or OCT stack). If the panel is missing, your deployment may not have the ETDRS form schema configured — contact your administrator.

### AI grid and your grids

When AI keypoints are present, the list starts with an **AI grid** row. It is a read-only preview. Your own grids are saved when you release a point.

### Workflow

1. Open a 2D enface image in the viewer.
2. Open **Layers › ETDRS grids**.
3. Optionally show the **AI grid** to preview AI-detected landmarks.
4. Click **New**: the grid becomes current and **Place ETDRS grid** (`G`) arms at **Fovea**.
5. Click the fovea. Press `]` (or **Disc edge** in the options bar) and click the optic disc edge. Drag a point to move it; **Del** removes the point under the pointer.
6. Use the eye button on a grid row to show or hide its overlay.

**Shift**+drag pans without placing a point.

Annotations from registered linked images may appear when registration connects them to the current view.

### Grid geometry

Three concentric circles represent **1 mm** (central), **3 mm** (inner), and **6 mm** (outer) ETDRS subfields. Scale uses the fovea–disc distance; the **Radius fraction** in ETDRS grids (default **0.85**, one for the whole viewer) treats that fraction of the distance as 3 mm.

### Keyboard shortcuts

| Keys | Action |
|------|--------|
| `G` | Place ETDRS grid |
| `[` / `]` | Fovea / Disc edge |
| Hold `Space` | Place the selected point and follow the pointer |
| `Del` | Remove the point under the pointer |
| `C`, then `[` / `]` | ETDRS circle at the pointer, C0 to O2 |

### Scale

Distance and the ETDRS circle share one scale per image: the stored resolution, else the current grid, else the only grid shown. Their scale button names the source and lets you pick another.

## Implementation & analysis

### Prerequisites (deployment)

The builtin FormSchema **`ETDRS-grid coordinates`** must exist in the database:

```bash
eorm seed-form-schemas
```

See **[Form schemas](/eyened-platform/orm/form_schemas)** for seeding and updates.

### Storage

| Source | Location | JSON shape |
|--------|----------|------------|
| Manual grid | `FormAnnotation.FormData` | `{ "fovea": {x,y}, "disc_edge": {x,y} }` |
| AI keypoints (automatic preview) | `AttributeValue` for **`CFI_Keypoints`**, or legacy `ImageInstance.CFKeypoints` column | `fovea_xy`, `disc_edge_xy` tuples |
| ETDRS field label (`F1`–`F7`, `WF`, `UWF`) | `ImageInstance.ETDRSField` **column** | Enum value (browser / Info panel only) |

Manual annotations use FormSchema **`ETDRS-grid coordinates`** (`EntityType.ImageInstance`). Coordinates are full-resolution pixel positions. Persisted via **[API — Forms](/eyened-platform/api/forms)**.

AI keypoints are written by **`eorm run-cfi-models`** (`cfi-keypoints`) or CFI import pipelines. The viewer reads them from API field **`cf_keypoints`** (not a `CFI_ETDRS` attribute). There is no platform attribute for ETDRS grid coordinates — only the form schema above.

Reserved attribute names and API field mapping: **[Attributes — reserved names](/eyened-platform/orm/data_model/attributes#reserved-attribute-names-platform-defined)**.

### Downstream analysis

ETDRS **area summaries** (segmentation counts per subfield) are computed by `eorm run-etdrs-model` using segmentations and attributes — see **[Inference](/eyened-platform/orm/inference)**.
