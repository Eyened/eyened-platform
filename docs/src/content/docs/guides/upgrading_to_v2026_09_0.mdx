## Fresh clone

Follow [Getting started](/eyened-platform/getting_started/).

## From v2026.08.0

Not a rolling upgrade: nothing may write to the database from step 1 to step 7.

Run `alembic` from `orm/migrations` with `-x env_file=<env>`, and `eorm` with `-e <env>`. The env file names an account with `ALL PRIVILEGES` on the database.

1. Stop the API, the workers, and every job that writes through `eyened_orm`.

2. Back up the database.

3. From the v2026.09.0 checkout, confirm there are no orphaned rows:

    ```bash
    eorm check-dangling-references
    ```

    Expect `No dangling references (5 hops checked).`

4. From a checkout of commit `6c675e5`, finish the legacy migrations:

    ```bash
    alembic upgrade b2e2800000b2
    ```

5. From the v2026.09.0 checkout, switch to the squashed history and migrate:

    ```bash
    alembic stamp --purge orm_baseline
    alembic upgrade head
    alembic check
    ```

    Expect `No new upgrade operations detected.`

6. Bootstrap access control:

    ```bash
    eorm init-admin --username <EYENED_API_ADMIN_USERNAME>
    eorm grant-all
    ```

    `grant-all` gives every existing account `grader` in every project. Remove unwanted accounts with `eorm revoke --user <username> --all`.

7. Rebuild every image that contains `eyened_orm`, upgrade `eyened_orm` wherever external jobs run, then start the platform.

## Rollback

Restore the backup from step 2 and redeploy v2026.08.0. Do not use `alembic downgrade`.
