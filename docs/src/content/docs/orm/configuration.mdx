## Configuration Options

The Eyened ORM is configured through environment variables. The sections below cover the
variables the ORM library itself reads. A deployment sets more than these: the server's secret
key, Redis, OIDC and worker settings are defined in `server/config.py`, and `deploy/.env.example`
is the reference for them.

### Database Settings

| Option | Required | Default | Description |
|--------|----------|---------|-------------|
| EYENED_DATABASE_USER | Yes | - | Database username |
| EYENED_DATABASE_PASSWORD | Yes | - | Database password |
| EYENED_DATABASE_HOST | No | `database` | Database host address |
| EYENED_DATABASE_DATABASE | No | `eyened_database` | Database name |
| EYENED_DATABASE_PORT | No | `3306` | Database port number |
| EYENED_DATABASE_RAISE_ON_WARNINGS | No | `true` | Whether to raise exceptions on database warnings |

### API Client Settings

| Option | Required | Default | Description |
|--------|----------|---------|-------------|
| EYENED_API_URL | With `APIClient` | - | Base URL of the Eyened API |
| EYENED_API_USERNAME | With `APIClient` | - | API login username |
| EYENED_API_PASSWORD | With `APIClient` | - | API login password |

These are read lazily, only when an `APIClient` is constructed; `Database()` and the `eorm`
commands never touch them. They are the ORM's API *client*, unrelated to the server's own
`EYENED_API_*` settings, which share the prefix and appear in the same `deploy/.env`.

### Storage Settings

Used by the ORM, workers, and thumbnail generation when reading/writing files locally.

| Option | Required | Default | Description |
|--------|----------|---------|-------------|
| EYENED_STORAGE_ROOT | No | `/storage` | Root directory for thumbnails (`thumbnails/`) and segmentations (`segmentations.zarr`) |
| EYENED_STORAGE_MOUNTS | No | `{}` | JSON object mapping storage backend keys to local filesystem paths (for image `ObjectKey` resolution) |

## Creating Environment Files

The most common way to configure the ORM is through `.env` files. The `deploy/` stack uses a
single `deploy/.env`; a standalone checkout can use a file of its own, with this structure:

```bash
# Database Settings
EYENED_DATABASE_USER=myuser
EYENED_DATABASE_PASSWORD=mypassword
EYENED_DATABASE_HOST=localhost
EYENED_DATABASE_DATABASE=eyened_database
EYENED_DATABASE_PORT=3306
EYENED_DATABASE_RAISE_ON_WARNINGS=true

# API Client Settings (only needed if using APIClient)
EYENED_API_URL=http://localhost:3000
EYENED_API_USERNAME=myuser
EYENED_API_PASSWORD=mypassword

# Storage (local file access — thumbnails, segmentations, import preparation)
EYENED_STORAGE_ROOT=/storage
EYENED_STORAGE_MOUNTS='{"local":"/path/to/images"}'
```

## Initialization Methods

The `Database` class can be initialized in several ways:

### 1. From Environment Variables

Load env vars (for example with `python-dotenv`), then initialize `Database()`:

```python
from eyened_orm import Database
from dotenv import load_dotenv

# Load environment variables from a .env file
load_dotenv("/home/bart/.env.dev")

# Reads settings from os.environ
database = Database()
```

### 2. From a Settings Object

Pass a `DatabaseSettings` instance directly:

```python
from eyened_orm import Database
from eyened_orm.config import DatabaseSettings

settings = DatabaseSettings(
    host="eyened-supergpu",
    port=16306,
    user="root",
    password="test",
)

database = Database(settings)
```

## Usage

Once initialized, you can use the database connection:

```python
from eyened_orm import Database

# Initialize database
database = Database()

# Context managed session (recommended - automatically closed)
with database.get_session() as session:
    # Use session for database operations
    pass

# Manual session management (must be closed manually)
session = database.create_session()
try:
    # Use session for database operations
    pass
finally:
    session.close()
```
