`eyened_orm.export` rebuilds selected [ImageInstances](/eyened-platform/orm/data_model/images) as DICOM files for sharing with other sites. Querying stays in your notebook or script; the module handles UIDs, OCT localizers, de-identification, and writing.

Requires an ORM session configured as in **[ORM setup](/eyened-platform/orm/getting_started)**.

:::note
This is an interchange format, not a round-trip of the original acquisition. Files are **Secondary Capture** (or multi-frame grayscale SC for OCT volumes), not Ophthalmic Tomography IODs. See [Why Secondary Capture](#why-secondary-capture).
:::

## Basic export

```python
import os
from pathlib import Path

from sqlalchemy import select

from eyened_orm import Database, ImageInstance, Patient, Project, Series, Study
from eyened_orm.export import DicomExportConfig, export_instances_to_dicom

output_dir = Path("/path/to/share/dicoms")
keyfile_path = Path("/path/to/keep-local/patient_id_keyfile.csv")

db = Database()
with db.get_session() as session:
    instances = session.scalars(
        select(ImageInstance)
        .join(Series)
        .join(Study)
        .join(Patient)
        .join(Project)
        .where(Project.ProjectName == "MyProject")
        .where(~ImageInstance.Inactive)
        .order_by(ImageInstance.ImageInstanceID)
    ).all()

    result = export_instances_to_dicom(
        session,
        instances,
        DicomExportConfig(
            output_dir=output_dir,
            pseudonymize_patient_ids=True,
            pseudonym_salt=os.environ["DICOM_EXPORT_PSEUDONYM_SALT"],
            offset_dates_per_patient=True,
            date_offset_salt=os.environ["DICOM_EXPORT_DATE_OFFSET_SALT"],
            keyfile_path=keyfile_path,
            image_keyfile_path=Path("/path/to/keep-local/image_filename_keyfile.csv"),
        ),
    )

print(f"Wrote {result.exported_count} files")
print(result.image_keyfile_path)
```

Both keyfiles must sit **outside** `output_dir` so they are not included in the share folder.

## Configuration

| Field | Default | Meaning |
|-------|---------|---------|
| `output_dir` | required | Directory for `.dcm` files only |
| `export_per_patient_subdir` | `True` | One subdirectory per (possibly pseudonymized) patient ID |
| `pseudonymize_patient_ids` | `False` | Replace `PatientID` with `prefix` + SHA-256 of `salt\|original_id` |
| `pseudonym_salt` | `""` | Required and non-empty when pseudonymizing |
| `pseudonym_prefix` | `"PID"` | Prefix for generated IDs |
| `offset_dates_per_patient` | `False` | Shift study and acquisition dates by a stable per-patient offset. Requires `pseudonymize_patient_ids` |
| `date_offset_salt` | `""` | Required and non-empty when offsetting dates |
| `date_offset_min_days` / `date_offset_max_days` | `-365` / `365` | Inclusive range for the offset |
| `keyfile_path` | `None` | **Required** when de-identifying; must resolve **outside** `output_dir` |
| `image_keyfile_path` | parent of `output_dir` when not de-identifying; **required** when de-identifying | Filename → `PublicID` and new UIDs; must be **outside** `output_dir` |
| `reuse_source_uids` | `False` | Reuse original Study/Series/SOP Instance UIDs. Cannot be combined with de-identification |
| `include_inactive` | `False` | If true, series-expansion may pull inactive localizers |

`DicomExportResult` reports `exported_paths`, `keyfile_path`, `image_keyfile_path`, `requested_count`, and `exported_count`. `exported_count` can be larger than `requested_count` when OCT localizers are pulled in.

## De-identification

Date offset cannot be used without pseudonymizing IDs. When `pseudonymize_patient_ids` is on:

- `PatientID` in the file, filename, and subdirectory is the pseudonym, never the source identifier
- New Study, Series, and SOP Instance UIDs are minted
- `PatientBirthDate` is omitted (not shifted)
- Device serial is omitted
- `PatientIdentityRemoved` / `DeidentificationMethod` are set
- `ContentDate` / `ContentTime` are the real export timestamp (not shifted)
- Each study gets one `StudyDate` / `StudyTime` (study date plus the earliest acquisition time, then shifted if date offset is on)
- `PatientSex` is still written
- Both keyfiles must be outside `output_dir` (mode `0600`)

Empty salts and a missing or in-share keyfile path raise `ValueError`.

:::caution
This is tag-level de-identification. Burned-in pixel text is not inspected; `BurnedInAnnotation` is set to `YES`.
:::

## What is written

Every file is Secondary Capture (`ConversionType = WSD`, `ImageType = DERIVED\SECONDARY`). OCT volumes with more than one frame use multi-frame grayscale SC.

| Source | DICOM |
|--------|--------|
| Patient ID (or pseudonym) | `PatientID` |
| Sex | `PatientSex` |
| Birth date (only if not de-identifying) | `PatientBirthDate` |
| Study date / earliest acquisition | `StudyDate` / `StudyTime` |
| `AcquisitionDateTime` | `AcquisitionDate` / `AcquisitionTime` |
| Scan mode, ETDRS field, disc/macula | `SeriesDescription` |
| Laterality | `ImageLaterality` and `Laterality` |
| `DICOMModality` (else `OP`) | `Modality` |
| Manufacturer / model | `Manufacturer` / `ManufacturerModelName` |
| Device serial (only if not de-identifying) | `DeviceSerialNumber` |
| Pixel size (see below) | `PixelSpacing` |
| `SliceThickness` / inter–B-scan spacing | `SliceThickness`, `SpacingBetweenSlices` |
| `HorizontalFieldOfView` | `HorizontalFieldOfView` |
| `PupilDilated` | `PupilDilated` (`YES`/`NO`) |
| Localizer SOP Instance UID | `ReferencedImageSequence` on OCT volumes |

**Pixel spacing** follows the [image axis conventions](/eyened-platform/orm/data_model/images):

- 2D: row = `ResolutionVertical`, column = `ResolutionHorizontal`
- OCT volume: row = `ResolutionAxial`, column = `ResolutionHorizontal`; `SpacingBetweenSlices` = `ResolutionVertical`

Filenames are `{patient}_{studyDate}_{laterality}_{Snnn}.dcm`. Instance numbers are 1..n within each series.

## OCT localizers

For an OCT volume (`NrOfFrames > 1` and modality name containing `OCT`), the exporter also writes likely localizers from the same series (infrared, SLO, fundus, or DICOM modality `OP`). Inactive series-mates are skipped unless `include_inactive=True`. Prefer images that share a storage directory with the OCT; otherwise it falls back to those heuristics. The OCT file references the **new** localizer SOP Instance UID.

## Why Secondary Capture

The catalog stores pixels and a handful of study tags, not a full Ophthalmic Tomography header. A valid OPT IOD needs frame-of-reference, per-B-scan pose, pixel-measure functional groups, and localizer coordinates. Those are read at [import](/eyened-platform/orm/importer) for series linking, then discarded.

Claiming the original OPT SOP Class on a thin rebuilt dataset is invalid DICOM. Secondary Capture is the class that matches the bytes we write: a derived image for interchange. To share a conformant OPT object, anonymize the **source DICOM** on disk (`ImageStorage.Format == "dicom"`) instead of rebuilding from the ORM row.

## Keyfiles

Patient keyfile (only when de-identifying):

```
original_patient_id,pseudonymized_patient_id,date_offset_days
```

Image keyfile (always written):

```
exported_filename,image_public_id,sop_instance_uid,series_instance_uid,study_instance_uid
```

`exported_filename` is relative to `output_dir`. Both files are created with mode `0600`. A later export to the same path **overwrites** the previous mapping; keep a copy if you need a historical ledger.
