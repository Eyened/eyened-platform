The renewed ORM importer turns **flat rows** (`ImportRow`) into a consistent set of ORM entities:

`Project → Patient → Study → Series → ImageInstance → ImageStorage` (plus device + storage backend)

At a high level:

- Build a list of `ImportRow` objects (or load them from CSV)
- Optionally enrich rows with [preparation](#row-preparation) (`PreparationOptions`: format inference, DICOM headers, OCT–enface series linking, hashes)
- Plan the import with `plan_image_import(session, rows, ...)` (or `build_image_import_rows` + `plan_import`) to produce an `ImportRun`
- Review the planned changes (`run.display_summary()` / `run.full_summary()`)
- Apply the changes (`run.apply()`), then `session.commit()`
- Optionally write the run to JSON for audit/undo (`run.write_json(...)`)
- After commit, generate thumbnails with [PostImport](/eyened-platform/thumbnails#importer-after-import) (import does not generate them automatically)

::::note
Planning may mutate ORM objects in-memory; nothing is persisted until you call `run.apply()` and commit the session.
`run.apply()` writes to the database but does not commit.
::::

Requires an ORM session configured as in **[ORM setup](/eyened-platform/orm/getting_started)**.

## Basic import (new images)

```python
from datetime import datetime

from eyened_orm.importer import plan_image_import, ImportRow

defaults = {
    "project_external": "Y",
    "manufacturer": "UNKNOWN",
    "manufacturer_model_name": "UNKNOWN",
    "device_description": "UNKNOWN",
    "dataset_identifier": "",  # deprecated, but required by schema
    "storage_backend_kind": "local",
}

rows = [
    ImportRow(
        project_name="demo-project",
        storage_backend_key="demo-backend",
        object_key="demo-0.png",
        patient_identifier="patient-1",
        study_date=datetime.now().date(),
        modality="ColorFundus",
        laterality="L",
    ),
    ImportRow(
        project_name="demo-project",
        storage_backend_key="demo-backend",
        object_key="demo-1.png",
        patient_identifier="patient-1",
        study_date=datetime.now().date(),
        modality="ColorFundus",
        laterality="R",
    ),
]

run = plan_image_import(session, rows, defaults=defaults)
run.display_summary()  # human-friendly overview (HTML in notebooks)

run.apply()
session.commit()
```

## Row preparation

Before planning, `plan_image_import` / `build_image_import_rows` call `prepare_rows` to fill missing fields. Control this with `PreparationOptions` (pass as `options=` to those helpers).

| Option | Default | Effect |
|--------|---------|--------|
| `infer_image_format` | `True` | Set `image_storage_format` from `object_key` (e.g. `.dcm` → `"dicom"`) |
| `defaults` | `None` | Fill missing row fields from a dict |
| `infer_metadata_from_dicom_header` | `False` | Parse DICOM headers (no pixels) and merge missing ImportRow fields |
| `link_oct_enface_series` | `False` | Co-locate OPT/OCT + enface under one `series_instance_uid` (reads linkage DICOM keys even without full-header infer) |
| `read_image_header` | `False` | Read PNG/JPEG dimensions |
| `compute_storage_hash` / `compute_storage_checksum` | `False` | SHA-256 / MD5 of file bytes |
| `raw_loader` | `None` | Optional `Callable[[ImportRow], bytes \| None]` instead of storage mounts |

**Merge rule:** preparation only fills fields that are still `None` and were **not** explicitly set on the `ImportRow`. Values you set on the row (or in `defaults`) always win — for example an explicit `patient_identifier` overrides DICOM `PatientID`. Passing `patient_identifier=None` pins the field blank so DICOM/defaults will not fill it; omitting the field leaves it unset so preparation may fill it.

**Reading files:** with `infer_metadata_from_dicom_header`, `link_oct_enface_series`, or hashes, bytes are loaded via `EYENED_STORAGE_MOUNTS[storage_backend_key] / object_key`, or via `raw_loader`. Use a **relative** `object_key` under the mount (not an absolute path).

```python
from eyened_orm.importer import ImportRow, PreparationOptions, plan_image_import

opts = PreparationOptions(
    defaults=defaults,
    infer_image_format=True,
    infer_metadata_from_dicom_header=True,
    link_oct_enface_series=True,
)
run = plan_image_import(session, rows, options=opts)
```

### DICOM header fields

When `infer_metadata_from_dicom_header=True` and `image_storage_format == "dicom"`, `dicom_header_patches_from_bytes` may fill (among others):

| DICOM source | ImportRow field |
|--------------|-----------------|
| `PatientID` | `patient_identifier` |
| `StudyDate` | `study_date` |
| `Modality` (+ heuristics) | `dicom_modality` and viewer `modality` |
| `SOPInstanceUID` / `SOPClassUID` | `sop_instance_uid` / `sop_class_uid` |
| `SeriesInstanceUID` / `StudyInstanceUID` / `SeriesNumber` | series fields |
| `Rows` / `Columns` / `NumberOfFrames` | `height` / `width` / `depth` |
| `PixelSpacing` / `SliceThickness` (top-level or Shared FG `PixelMeasuresSequence`) | `resolution_*` |
| Laterality / acquisition datetime | `laterality` / `acquisition_date_time` |

**Viewer modality heuristics** (Spectralis-oriented; leave `modality` unset when ambiguous):

- `OPT` → `dicom_modality=OPT`, `modality=OCT` (OCTA is **not** auto-detected)
- `OP` + `ImageType` containing `RED` → `InfraredReflectance`
- `OP` + `ImageType` containing `AF` → `Autofluorescence`
- `OP` without those subtypes → `dicom_modality=OP` only
- Other DICOM modalities (e.g. `OT` device raw data) → neither modality field set; usually skip those files at row-building time

Preparation logs **warnings** when OPT→OCT mapping is used, when OP has no viewer modality, or when series linking cannot run (see below).

### OCT–enface series linking

Some exports (notably Heidelberg) give each file its own `SeriesInstanceUID`, while OCT and the IR/AF localizer still belong together. They typically share `FrameOfReferenceUID`, and the OPT references the enface via `ReferencedImageSequence` / Ophthalmic Frame Location.

With `link_oct_enface_series=True`, preparation builds a parallel `SeriesLinkMeta` from the DICOM header (modality classification, FrameOfReferenceUID, referenced SOPs) and only merges series/SOP UID fields into the row when `infer_metadata_from_dicom_header=False`. It then:

1. Finds OPT/OCT rows and their referenced enface SOP UIDs (FoR fallback if needed)
2. Sets all members of each pair/group to the **OCT’s** `series_instance_uid`

So they land in one `Series` for the viewer and for export localizer heuristics. Rows with an explicit `series_id` or an explicitly set `series_instance_uid` are left alone. Confirmed links still apply if `series_anonymous_identity` is set (otherwise distinct DICOM series UIDs would keep the pair apart). Modality is **not** written to the row unless `infer_metadata_from_dicom_header=True` (or you set it yourself).

::::caution
If `link_oct_enface_series=True` but DICOM bytes cannot be read (unreadable mounts/`object_key`, or missing FoR/references), linking is a **no-op** and a warning is logged.
::::

## Import from CSV

If you already have metadata in a CSV, you can load it directly into `ImportRow` objects.
The CSV header should use `ImportRow` field names (snake_case), for example `project_name`, `patient_identifier`, `study_date`, `public_id`, `object_key`, ...

Empty CSV cells are omitted (field unset), so preparation may still fill them from DICOM or `defaults`. To leave a field blank on purpose, build the row in Python with an explicit `None`.

```python
from pathlib import Path

from eyened_orm.importer import plan_image_import
from eyened_orm.importer.import_csv import read_import_rows_csv

csv_path = Path("rows.csv")
rows = read_import_rows_csv(csv_path)

run = plan_image_import(session, rows, defaults=defaults)
run.display_summary()
run.apply()
session.commit()
```

## Attaching to existing objects

If part of the hierarchy already exists, rows can attach to it using:

- Primary keys (`*_id`) **or**
- Lookup fields (for example `project_name` + `patient_identifier` + `study_date`)

Primary keys take precedence when provided.

## Grouping into the same Series (batch-local)

When you don’t have a stable real-world identifier (for example no DICOM `series_instance_uid`), you can group rows **within the same import batch** using `*_anonymous_identity`.

Rows with the same `series_anonymous_identity` will be grouped into the **same `Series`**.

For DICOM OCT + enface that already have UIDs but should share a series, prefer [`link_oct_enface_series`](#octenface-series-linking) instead of inventing anonymous identities.

## Reviewing changes in detail

To inspect a per-entity/per-field view of what will change:

```python
print(run.full_summary())
```

## Audit trail (write/read JSON) and undo

After a successful run (`run.status == "done"`), you can write an audit/undo JSON that stores entity references by primary key:

```python
from pathlib import Path
from eyened_orm.importer import ImportRun

json_path = Path("import_run.json")
run.write_json(json_path)

loaded = ImportRun.read_json(session, json_path)
loaded.undo()
session.commit()
```

## Patch existing entities (example: update laterality by `public_id`)

For patching, you only need enough identity to resolve the existing entity plus the fields you want to change.

```python
from eyened_orm.importer import plan_image_import, ImportRow

rows_patch = [
    ImportRow(public_id="i22rza47rkzi", laterality="R"),
    ImportRow(public_id="ph1p02fsx4ab", laterality="R"),
]

run_patch = plan_image_import(session, rows_patch)
run_patch.display_summary()
run_patch.apply()
session.commit()
```

## Special cases

- **Project only**: provide `project_name` (and any project fields you want to set)
- **Project + Patient**: add `patient_identifier`

## Expected behaviors (covered by tests)

- **Reject early**: missing required parent identity fails during planning.
- **Deduplication**: rows with the same lookup key are merged into one create + updates.
- **Idempotency**: re-running the same import should not produce any changes.
- **Primary-key precedence**: if `*_id` is provided, it wins over lookup keys (and allows renaming lookup fields).
- **DICOM preparation**: PatientID/StudyDate/modality/resolutions and OCT–enface series linking (see tests in `orm/eyened_orm/importer/tests/test_preparation_dicom_and_hashes.py`).
