# Eyened ORM CLI

The Eyened ORM includes command line utilities for database setup, maintenance, model inference, and validation. Commands are available through the `eorm` CLI.

:::note
Use the global help to list all commands:

```bash
eorm --help
```

Use command help to inspect current options:

```bash
eorm [COMMAND] --help
```
:::

## Available Commands

### initialize-database

Creates tables from the ORM on an empty database and stamps the current Alembic revision so later `alembic upgrade head` runs apply only new migrations. Prompts for confirmation of the target database.

```bash
eorm initialize-database [OPTIONS]
```

Use `--seed-form-schemas` to also insert builtin viewer FormSchema rows in the same step.

### seed-form-schemas

Inserts builtin viewer FormSchema rows required by the ETDRS grid and registration panels. Idempotent: existing schemas are skipped unless `--update` is passed.

```bash
eorm seed-form-schemas [--update]
```

See **[Form Schemas](/eyened-platform/orm/form_schemas)** for the list of seeded schemas and how to add clinical forms.

### create-user

Creates a database user with login credentials and metadata.

```bash
eorm create-user [OPTIONS]
```

### update-thumbnails

Generates thumbnails for images with missing (or optionally failed) `ThumbnailPath`. Equivalent to `POST /api/import/update_thumbnails` but runs in-process (no worker).

With no target flags, scans the whole database. Scope a subset with `--path`, `--image-ids`, `--project`, or `--patient` (same targeting options as inference commands).

See **[Thumbnails](/eyened-platform/thumbnails#cli)** for options and behavior.

### run-models

Runs attribute inference models on a scoped set of images.

```bash
eorm run-models [OPTIONS]
```

### run-segmentation

Runs segmentation inference models on a scoped set of images.

```bash
eorm run-segmentation [OPTIONS]
```

### run-etdrs-model

Runs ETDRS summary processing using model segmentations and related model outputs.

```bash
eorm run-etdrs-model [OPTIONS]
```

## Targeting

Image- and patient-scoped commands share the same targeting flags. Provide **at least one** of:

| Flag | Description |
|------|-------------|
| `-p` / `--path` / `--image-ids-file` | File with one `ImageInstanceID` or `PublicID` per line (`#` comments ok) |
| `--image-ids` | Comma-separated `ImageInstanceID` or `PublicID` values (small lists) |
| `--project` | Project ID or project name |
| `--patient` | Patient identifier; combine with `--project` when the identifier exists in multiple projects |
| `--exclude` / `--skip` | Comma-separated IDs or PublicIDs to exclude (image commands) or skip (registration) |
| `--modality` | Filter by modality when expanding `--project` or `--patient` |

Examples:

```bash
eorm run-models --project "AMD-Study" --modality ColorFundus
eorm run-segmentation --path ids.txt
eorm run-registration --project "AMD-Study" --patient amd001
eorm run-registration --project 1 --skip abc12def,1811325
eorm update-thumbnails --project "AMD-Study"
```

When no target flags are given, `update-thumbnails` and `update-hashes` scan the whole database (previous behavior).

### run-registration

Runs pairwise registration for enface images (color fundus, autofluorescence, and infrared reflectance) using the `retinalysis-registration` model. For each patient, transforms are stored in a patient-level **Registration** attribute as JSON: a list of `{image1, image2, transform}` records.

You must scope the run with either `--patient` (patient identifier) or `--project` (project ID). Without `--replace`, existing transforms are kept and only missing pairs are computed. With `--replace`, stored transforms are cleared first. Use `--skip` to exclude specific image instance IDs (comma-separated).

Requires the optional `rtnls_registration` package and ORM database configuration (see [ORM Configuration](/eyened-platform/orm/configuration)).

```bash
eorm run-registration --patient PATIENT_IDENTIFIER
eorm run-registration --project 1
eorm -e /path/to/.env run-registration --project 1 --replace
eorm run-registration --patient PATIENT_IDENTIFIER --skip 1811325,1811324
```

See `eorm run-registration --help` for all options.

### validate-forms

Validates form annotations and schemas stored in the database.

```bash
eorm validate-forms [OPTIONS]
```

### zarr-tree

Prints the structure of the configured zarr store, including groups and arrays.

```bash
eorm zarr-tree [OPTIONS]
```

### defragment-zarr

Copies segmentations to a new zarr store with sequential indices to reduce fragmentation.

```bash
eorm defragment-zarr [OPTIONS]
```

### update-hashes

Updates missing `FileChecksum` and `DataHash` values for image instances.

```bash
eorm update-hashes [OPTIONS]
```

### load-dump

Loads a SQL dump into the target database after dropping and recreating it.

```bash
eorm load-dump [OPTIONS]
```

:::caution
`load-dump` is destructive and replaces all existing data in the configured database.
:::

### save-dump

Creates a dated SQL dump of the configured database.

```bash
eorm save-dump [OPTIONS]
```
